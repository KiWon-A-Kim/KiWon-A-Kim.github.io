## 다음 작업의 실행 순서

1. `git status --short --branch`를 확인하고 기존 사용자 변경사항을 보존한다.
2. 이 문서와 README를 읽고 요청을 위 ID에 연결한다. 새 정보와 관련된 파일만 우선 읽는다.
3. 제공된 사실만 반영한다. 회사 값은 `assets/site.js` 한 곳에서, 본문은 해당 HTML의 한국어·영어 양쪽에서 수정한다.
4. 연락처·앱 이름·출시 상태 변경 시 홈, 앱 소개, 정책, 삭제 안내 사이의 불일치를 확인한다. `<title>`·description도 필요에 따라 갱신한다.
5. 페이지 추가·삭제 시 공통 헤더/푸터, 영어 영역, 인증 주석, 루트 기준 링크 및 `sitemap.xml`을 함께 처리한다.
6. `python scripts/check_site.py`와 `git diff --check`를 실행한다. UI 변경은 가능할 때 실제 브라우저로 확인하고, 불가능하면 그 한계를 보고한다.
7. 이 문서의 상태와 README의 미정 항목 목록·개수를 현재 파일에 맞게 갱신한다. 완료 항목은 날짜·근거·검증 결과를 기록한다.
8. 해당 요청에서 배포까지 진행하는 경우 커밋/푸시 후 최신 SHA의 Pages 결과와 실서비스 반영을 확인한다. 미확인 또는 대기 상태를 완료라고 보고하지 않는다.

미정 표시 재검색(문서에 인용된 예시는 제외):

```powershell
rg -n '\{\{[^{}]+\}\}' -g '*.html' -g '*.js'
python scripts/check_site.py
git diff --check
```
